# 开发计划与设计约定

本文记录本次任务的实施计划、接口约定和文件归属。所有参与开发的智能体都必须遵守本文。若本文与 `LLM_notice/如果你是LLM请看这里.md` 冲突，以该任务说明为准。

## 一、总体路线

1. 保留并修复原有目录结构，不引入需要运行时动态链接库的外部库。
2. 公共类型、地图、日志、JSON、配置、核心游戏、通信、界面、编排全部重写为可编译可测试状态。
3. 根目录 `build.bat` 负责构建 `serve.exe` 和示例玩家。
4. `battle/example` 为参考 AI，另有三个演示玩家用于多玩家模式测试。
5. 测试通过 `--no-ui` 无界面模式自动执行，结果写入 `LLM_notice/`。
6. 最终提交到分支 `feature/complete-generals-io`，不提交到 `main`。

## 二、构建约束

- 编译器为 MinGW GCC，标准为 `gnu++20`，必须 `-static` 静态链接。
- 图形库使用仓库内 `lib/easyx`，以 `-Llib/easyx/lib -leasyx -lgdi32 -lole32 -lwinmm -lgdiplus` 链接。
- EasyX 头文件会产生 `#pragma comment` 警告，构建时加 `-Wno-unknown-pragmas`。
- 不允许在运行时依赖 MinGW 的动态库。
- 源文件字符集和执行字符集均为 UTF-8。

## 四、代码风格

- 注释使用中文。少用标点，多用空格。
- 变量名首单词小写，后续单词首字母大写。函数名同规则。类名全部单词首字母大写。命名空间全部小写。
- 命名空间：`gen`，子目录用 `gen::core` `gen::io` `gen::ui`。
- 头文件用 `.hpp`。
- 不使用动态库。
- 简单函数内联并写在 `.hpp` 中。
- 所有公开函数必须在头文件注释里说明参数、返回值和作用。公开变量说明类型与用途。

## 五、通信协议最终版

本协议写入 `选手须知.md`，实现必须与本文一致。

### 5.1 基本约定

- 游戏程序与 AI 程序通过 AI 程序的标准输入和标准输出传递二进制消息。标准错误只用于调试输出。
- 所有整数为小端序。
- 坐标从 0 开始，`(x, y)` 中 `x` 为行，`y` 为列，行优先下标 `idx = x * C + y`。
- 玩家编号与队伍编号从 0 开始。
- 游戏程序发给 AI 程序的每条消息为长度前缀帧：

```text
uint32 length   // payload 字节数 不含 length 本身
uint8  payload[length]  // payload[0] 为消息类型
```

- AI 程序发给游戏程序的每条消息为一行 ASCII 文本，以 `\n` 结尾，可带 `\r`。每回合只读取第一行。
- 初始化时限从游戏程序发送完 `INIT` 起算，默认 2 秒，到收到 `READY` 行止。
- 每回合时限从发送完 `GO` 起算，默认 50 毫秒，到收到完整动作行止。
- 单次超时、非法输出、非法移动按 `PASS` 处理并记一次违规。违规连续达到配置上限时判负。
- 进程崩溃、主动退出、输出关闭、初始化和对局期间永久无响应均判负。

### 5.2 消息类型

| type | 名称 | 方向 | 说明 |
| ---: | --- | --- | --- |
| 1 | `PLAYER_SELF` | 游戏程序发给 AI | 自己的信息 |
| 2 | `PLAYERS` | 游戏程序发给 AI | 全部玩家，按初始移动优先级从高到低 |
| 3 | `MAP_META` | 游戏程序发给 AI | 地图大小 |
| 4 | `MAP` | 游戏程序发给 AI | 初始视野地图 |
| 5 | `INIT` | 游戏程序发给 AI | 初始化开始，AI 回复 READY |
| 6 | `TURN` | 游戏程序发给 AI | 回合数、玩家状态、队伍排名、视野地图 |
| 7 | `GO` | 游戏程序发给 AI | 开始计时，AI 回复动作行 |
| 8 | `GAME_OVER` | 游戏程序发给 AI | 最终排名，发送后关闭连接 |

### 5.3 帧格式

`PLAYER_SELF`：

```text
uint16 playerID
uint16 teamID
uint8  idLen
char   id[idLen]   // ASCII 玩家文件夹名 长度不超过 64
```

`PLAYERS`：

```text
uint16 N
重复 N 次
    uint16 playerID
    uint16 teamID
    uint8  idLen
    char   id[idLen]
```

`MAP_META`：

```text
uint16 R
uint16 C
```

`MAP` 的 payload 为 `map_payload`：

```text
uint8  terrain[R * C]   // 行优先 地形编码见 5.5
int16  owner[R * C]     // -1 中立 -2 未知 其余为玩家编号
uint32 units[R * C]     // 可见格为真实兵力 未知格为 0
```

`TURN`：

```text
uint32 turn
uint16 N
重复 N 次
    uint16 playerID
    uint16 teamID
    uint8  alive        // 0 已淘汰 1 存活
    uint32 tiles
    uint32 units
uint16 T
重复 T 次
    uint16 teamID
    uint16 rank         // 1 为第一名
map_payload
```

玩家状态按当前回合移动优先级从高到低发送。队伍排名覆盖全部队伍，从高到低。

`GAME_OVER`：

```text
uint16 N
重复 N 次
    uint16 playerID
    uint16 rank
    int32  deathTurn    // -1 表示存活
uint16 T
重复 T 次
    uint16 teamID
    uint16 rank
```

### 5.4 初始化流程

1. 游戏程序启动 AI 程序，工作目录为 `battle/<id>`，可执行文件为 `battle/<id>/<id>.exe`。
2. 游戏程序依次发送 `PLAYER_SELF`、`PLAYERS`、`MAP_META`、`MAP`、`INIT`。
3. AI 程序读取到 `INIT` 后初始化，并在时限内输出一行 `READY`。
4. 初始化失败或超时判负。

### 5.5 每回合流程与动作

1. 游戏程序发送 `TURN` 帧。
2. 游戏程序发送 `GO` 帧并开始计时。
3. AI 程序在时限内输出一行动作。
4. 游戏程序校验并执行动作。

动作行只允许以下三种：

```text
PASS
M x1 y1 x2 y2
H x1 y1 x2 y2
```

- `M` 表示普通移动，从源格移动 `u - 1` 个兵力，源格保留 1 个兵力。
- `H` 表示一半移动，源格保留 `floor(u / 2)` 个兵力，移动 `u - floor(u / 2)` 个兵力。
- `u` 为源格兵力，必须大于等于 2。
- 源格必须为己方占领，目标格必须与源格曼哈顿距离为 1。
- 目标格不能是山区。
- 非法动作按 `PASS` 处理。

### 5.6 地形与视野编码

地形编码：

| 编码 | 名称 | 含义 |
| ---: | --- | --- |
| 0 | Blank | 空地 |
| 1 | Mountain | 山区 |
| 2 | Swamp | 沼泽 |
| 3 | City | 城市 |
| 4 | Capital | 首都 |
| 5 | FogBlank | 疑似空地 空地或首都 |
| 6 | FogMountain | 疑似山区 山区或城市 |
| 7 | FogSwamp | 视野外沼泽 |

视野规则：视野内格子的地形、归属、兵力都是真实值。视野外的格子按疑似编码发送，`owner = -2`，`units = 0`。

## 六、移动与回合规则最终版

- 每名玩家每回合最多移动一次。源格必须为己方占领。
- 普通移动预留 1 个兵力。一半移动预留 `floor(u / 2)` 个兵力。
- 目标为己方或队友格子时，兵力相加，归属不变。
- 目标为敌方或中立格子时，比较移动兵力和目标兵力。
- 移动兵力大于目标兵力时占领目标格，剩余兵力为两者之差。目标为敌方首都时，被占领首都变为城市，被击败玩家的全部格子归进攻方，非首都格兵力向上取整减半。
- 移动兵力小于等于目标兵力时，目标兵力减少移动兵力，归属不变。
- 回合处理顺序：回合数加一，按优先级执行移动，处理兵力生成与消失，判断胜负，计算视野与排名。
- 城市和首都在偶数回合加 1 个兵力。空地在回合数为 50 的倍数时加 1 个兵力。沼泽每回合减 1 个兵力，最低减到 1。
- 移动优先级每回合轮转一位，当前最高优先级玩家变为最低。
- 剩余队伍数为 1 时游戏结束。到达最大回合数仍未结束时按队伍排名与兵力排名。

## 九、实现完成情况

本节记录实际落地时与原计划的差异与补充。

1. 测试用 PowerShell。开发机只有 Windows PowerShell 5.1，测试脚本改为兼容 5.1 并以 UTF-8 BOM 保存。主推命令为 `powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1`。脚本共 47 项断言，全部通过。
2. 命名空间。基础类型与工具位于 `gen`。`src/include/map.hpp` 的 `Tile` 与 `GameMap` 位于 `gen::core`，因为它们是核心玩法类型。其余子目录按 `gen::core`、`gen::io`、`gen::ui` 划分。文档按实际约定说明。
3. 非法移动处理。Runner 在收集动作时用本回合开始前的地图预校验。棋盘非法的移动按 PASS 计一次违规。被更高优先级玩家抢先结算而失效的合法移动按 PASS 不计违规。该策略已写入 `选手须知.md`。
4. JSON 兼容。解析器容忍 UTF-8 BOM，遇到 UTF-16 或 UTF-32 字节顺序标记给出明确中文提示。PowerShell 5.1 的 `Set-Content -Encoding utf8` 会写 BOM，因此测试脚本生成配置时改用无 BOM 写法。
5. AI 示例。额外提供 demo_expand、demo_random、demo_rush 三个演示玩家，使 2v2、FFA、自动匹配可以开箱测试。四个玩家都有 icon.png 供界面使用。
6. 界面限制。同一进程内 `closegraph` 后再次 `initgraph` 存在 EasyX 库缺陷。Runner 每个进程只打开一次界面，不受影响。界面自动化验证只能做到进程级冒烟与人工观察，像素级效果未自动断言。
7. 环境限制。开发会话的 Windows 沙箱对工作区部分目录有权限与完整性标签限制。本次开发做过一次目录权限整理，只影响开发机环境，不进入提交内容。普通用户按 README 步骤即可构建运行。
8. 提交内容。源码、配置、玩家源码与图标、文档、测试脚本与测试 AI 源码进入 Git。`serve.exe`、`battle/*/*.exe`、`build/`、`logs/` 为运行产物，由 `.gitignore` 排除。
