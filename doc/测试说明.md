# 测试说明

本文说明本项目的自动化测试方案、测试项、运行方法、结果查看方法和新增测试的方法。

测试脚本是 `tests\run_tests.ps1`。它用无界面模式跑全部验收测试。

## 一 测试目标与原则

测试目标：

1. 验证项目能干净构建。
2. 验证主要游戏模式能运行。
3. 验证主要配置项生效。
4. 验证异常 AI 能被正确处理。
5. 验证常见错误有明确提示。

测试原则：

- 全部测试使用 `--no-ui` 无界面模式。
- 每个测试记录命令、配置、退出码和关键日志。
- 测试结果用 `PASS` 与 `FAIL` 标记。
- 测试不能依赖人工观察。
- 禁止伪造测试结果。
- 不能自动测的项目要写原因。

## 二 前置条件

运行测试前需要准备：

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 或 Windows 11 |
| 编译器 | `g++` 在 PATH 中，支持 C++20 |
| PowerShell | Windows 自带的 Windows PowerShell 5.1 或更高版本 |
| 脚本编码 | `tests\run_tests.ps1` 必须保存为 UTF-8 BOM |
| 工作目录 | 仓库根目录 |
| 磁盘空间 | 能写入 `build\test_output` |

`g++` 的安装见 [构建与环境](构建与环境.md)。

不需要安装 PowerShell 7。Windows 自带的 `powershell` 就是 5.1 版本，测试脚本已经兼容。

如果已经安装了 PowerShell 7，也可以使用 `pwsh`。

### 2.1 UTF-8 BOM 要求

`tests\run_tests.ps1` 必须保存为 UTF-8 BOM 编码。

原因：

- Windows PowerShell 5.1 读取没有 BOM 的 UTF-8 文件时，会按系统 ANSI 代码页解码。
- 脚本里有中文注释和中文字符串，按 ANSI 解码会乱码，甚至导致语法错误。

检查和保存方法：

1. 用 VS Code 打开 `tests\run_tests.ps1`。
2. 点右下角编码按钮，选择 `通过编码保存`，再选 `UTF-8 with BOM`。
3. 保存后用十六进制工具确认文件开头为 `EF BB BF`。

## 三 运行方法

### 3.1 基本命令

在仓库根目录运行：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `powershell` | Windows 自带的 Windows PowerShell 5.1 |
| `-NoProfile` | 不加载个人配置，避免环境差异 |
| `-ExecutionPolicy Bypass` | 只对本次运行放宽脚本执行策略 |
| `-File` | 指定要运行的脚本路径 |

如果已经安装了 PowerShell 7，也可以改用：

```pwsh
pwsh -File tests\run_tests.ps1
```

### 3.2 可选参数

| 参数 | 作用 |
| --- | --- |
| `-SkipBuild` | 跳过干净构建测试，直接使用已有的 `serve.exe` |
| `-SkipUi` | 跳过界面冒烟测试 |
| `-KeepLogs` | 保留上一次的测试输出，不先删除 `build\test_output` |

例如只跑逻辑测试，不跑界面：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1 -SkipUi
```

已经构建好程序，只看逻辑：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1 -SkipBuild -SkipUi
```

### 3.3 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部测试通过 |
| 1 | 至少一项测试失败，或脚本异常 |

## 四 测试脚本做了什么

测试脚本的流程：

1. 记录仓库根目录，切换到根目录。
2. 准备 `build\test_output` 目录。没有 `-KeepLogs` 时先清空。
3. 清理可能残留的 `battle\test_timeout`、`battle\test_crash`、`battle\test_invalid`、`battle\test_illegal_move` 目录。
4. 检查 `g++` 是否可用。
5. 干净构建。删除 `serve.exe` 和四个示例玩家的 exe，然后调用 `cmd /c build.bat --no-pause`。
6. 检查构建产物。检查四个示例玩家 exe 是否存在，用 `objdump` 检查静态链接。
7. 跑 `config/example.json`，检查退出码、日志、操作记录、计分日志。
8. 跑 1v1、2v2、FFA 三个预设配置。
9. 跑自动匹配配置，检查玩家发现数和比赛场数。
10. 生成测试配置，跑禁用地形和最大回合数。
11. 编译四个异常 AI，跑 AI 超时、AI 崩溃、AI 非法输出、AI 非法移动。
12. 删除临时测试玩家目录，避免影响后面的玩家枚举。
13. 跑配置缺失、日志目录自动创建、玩家可执行文件缺失、自动匹配人数不足。
14. 跑界面冒烟测试。有交互桌面时启动界面模式，5 秒内进程应保持运行。还会检查日志里有界面窗口记录。
15. 生成测试报告，返回退出码。

每个测试项用 `Check` 函数记录结果。控制台会输出 `[PASS]` 或 `[FAIL]`，并带测试名和说明。

当前脚本共有 47 项检查。最近一次运行全部通过。

测试脚本会实时打印：

```text
[PASS] 干净状态构建 build.bat exit=0 serve.exe=True
[FAIL] 自动匹配生成组合 期望 6 场比赛
```

最后打印通过数与失败数。

```text
build\test_output\report.md
```

| `build\test_output\<测试名>.stderr.txt` | 该测试的标准错误 |
| `build\test_output\logs_<测试名>\serve.log` | 该测试配置的主日志 |
| `build\test_output\configs\<测试名>.json` | 该测试使用的配置 |
| `build\test_output\example.serve.log` | 示例配置的主日志副本 |
| `build\test_output\example.moves.log` | 示例配置的操作记录副本 |

原始日志同时在仓库的 `logs` 目录下。每次运行会覆盖。

### 7.4 单项失败怎么查

1. 打开 `build\test_output\report.md`，找到 `FAIL` 项。
2. 看说明列里的原因。
3. 打开对应测试的 `.stdout.txt` 和 `.stderr.txt`。
4. 打开对应配置的 `serve.log`，搜索 `ERROR` 和 `WARN`。
5. 用 `build\test_output\configs` 里的配置手动复现：

```bat
serve.exe --config build\test_output\configs\crash.json --no-ui --no-pause
```

6. 检查 `logs\ai` 下对应玩家的标准错误输出。
7. 修复后重新运行测试脚本。

## 八 如何新增测试

新增测试的一般步骤：

1. 确定测试目标与预期结果。
2. 如需要特殊 AI，在 `tests\ai` 下新增源码。
3. 在 `tests\run_tests.ps1` 里增加测试段。
4. 使用 `New-TestConfig` 生成配置。
5. 使用 `Invoke-Serve` 运行。
6. 使用 `Check` 记录断言。
7. 清理临时文件。
8. 运行脚本确认通过。

### 8.1 新增测试用的 AI

在 `tests\ai` 下新建 `.cpp` 文件。复用 `protocol_util.hpp` 里的读帧与写行函数。

编译命令：

```bat
g++ -std=gnu++20 -O2 -static -o battle\test_xxx\test_xxx.exe tests\ai\xxx.cpp
```

测试 AI 的命名要求：

- 目录名与 exe 文件名一致。
- 目录名只用字母、数字、下划线、短横线。
- 测试结束后删除目录。

### 8.2 新增测试段

示例：

```powershell
Write-Host '== 新测试项 =='
$config = New-TestConfig 'newcase' {
    param($config)
    $config.game.maxTurns = 3
}
$result = Invoke-Serve 'newcase' $config
$log = Get-TestLog 'newcase'
Check '新测试项运行' ($result.ExitCode -eq 0) ("exit=" + $result.ExitCode)
Check '新测试项日志' ($log -match '关键字') '日志应包含关键字'
```

可用函数：

| 函数 | 作用 |
| --- | --- |
| `New-TestConfig -Name <名字> -Modify <脚本块>` | 以 `config\example.json` 为模板生成测试配置。会自动关闭界面，并把日志目录设为 `build/test_output/logs_<名字>` |
| `Invoke-Serve -Name <名字> -ConfigPath <配置> -ExtraArgs <参数>` | 用 `--no-ui --no-pause` 运行 `serve.exe`，保存标准输出与标准错误，返回退出码和文件路径 |
| `Get-TestLog -Name <名字>` | 读取该测试配置的主日志 |
| `Check -Name <名字> -Condition <条件> -Detail <说明>` | 记录一条断言，打印并写入报告 |
| `Install-TestPlayer -Id <玩家> -SourceRelative <源码>` | 编译测试 AI 到 `battle\<玩家>\<玩家>.exe`，测试结束时自动清理 |
| `Write-Report` | 生成测试报告，返回失败数 |

### 8.3 断言建议

优先断言：

1. 进程退出码。
2. `serve.log` 里的关键字。
3. 关键文件是否存在。
4. 操作记录内容。
5. 计分日志内容。

不建议断言：

- 具体的地图布局。
- 具体的时间值。
- AI 的随机动作。
- 界面像素内容。

### 8.4 新增测试的注意事项

- 测试必须使用无界面模式。
- 测试配置要独立日志目录，避免互相覆盖。
- 测试要固定随机种子，方便复现。
- 测试不能依赖网络。
- 测试不能依赖人工点击。
- 测试结束要清理临时玩家目录和进程。
- 测试超时要有上限，不能无限等待。
- 新增测试后要实际运行，确认通过。不能只写断言不运行。

## 九 已知限制

1. 界面冒烟测试需要交互桌面。没有桌面时脚本跳过该项并记通过。
2. 干净构建测试会删除 `serve.exe` 与四个示例玩家 exe。运行前要关闭正在运行的程序。
3. 测试会临时创建 `battle\test_timeout`、`battle\test_crash`、`battle\test_invalid`、`battle\test_illegal_move` 目录。测试运行时不要手动修改 `battle`。
4. 测试时间取决于对局长度。示例配置的 1v1 可能跑较久，可以调小 `maxTurns`。
5. 测试脚本生成 `build\test_output\report.md`，不会自动写 `LLM_notice\测试报告.md`。归档由验收人员手工完成。
6. 静态链接检查依赖 `objdump`。没有 `objdump` 时该项跳过并记通过。
7. 测试脚本必须保存为 UTF-8 BOM 编码，否则 Windows PowerShell 5.1 读取中文会乱码。
8. 测试覆盖的是主要路径，不是全部边界。协议边界、极端配置、超大地图等可以按需补充测试。
