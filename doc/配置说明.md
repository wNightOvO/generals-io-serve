# 配置说明

本文说明 `config/` 目录下的 JSON 配置文件。读完后可以自己修改配置，也可以自己新建配置。

## 一、配置文件说明

程序启动时读取一个 JSON 配置文件。配置文件决定地图大小、对局规则、比赛方式、界面显示与日志输出。

配置文件位于 `config/` 目录。当前仓库共 26 个配置键，分为 `map` `game` `match` `ui` `log` 五段。

### 1.1 怎么指定配置文件

通过命令行参数 `--config` 或 `-c` 指定配置文件路径。

```text
serve.exe --config config\2v2.json
serve.exe -c config\ffa.json --no-ui
```

省略 `--config` 时使用默认配置 `config/example.json`。

相对路径以运行程序时的工作目录为准。一般在仓库根目录运行 `serve.exe`，所以写成 `config\xxx.json`。路径中带空格时用英文双引号包住。

其他命令行参数如下。

| 参数 | 作用 |
| --- | --- |
| `--config <路径>` 或 `-c <路径>` | 指定配置文件，默认 `config/example.json` |
| `--no-ui` | 不显示图形界面，适合批量测试与自动运行 |
| `--seed <数字>` | 指定基础随机种子，便于复现对局，优先级高于 `map.seed` |
| `--no-pause` | 出错退出时不等待按键，适合脚本调用 |
| `--help` 或 `-h` | 显示帮助信息 |

### 1.2 配置文件不存在或非法时的行为

配置文件在启动最早阶段读取并校验，之后才创建日志目录和界面窗口。所以配置出错时不会留下窗口，也不会生成日志文件。

出现以下情况时程序把中文错误提示写到标准错误，然后退出，退出码为 1。

- 配置文件不存在。
- 文件不是合法 JSON，例如少了括号、多了逗号、用了注释。
- 根节点不是 JSON 对象。
- 某个键的类型不对，例如把整数写成了字符串。
- 某个键的取值越界，例如地图行数写成 3。
- 枚举值未知，例如模式写成 `3v3`。
- 显式队伍配置与模式不匹配，例如 1v1 配了三支队伍。

错误提示会给出配置文件绝对路径与出错位置。JSON 语法错误给出第几行第几列。取值错误给出配置键路径与当前值。

例如：

```text
配置错误 配置文件不存在 config\my.json
配置错误 解析配置文件 config\my.json 失败 第 3 行 第 5 列 对象的键之后缺少冒号
配置错误 配置键 map.rows 必须是 5 到 200 的整数 当前为 3
```

缺少某个键不算错误。程序使用该键的默认值，并写一条警告，提示使用了默认值。未知的键不参与运行。程序写一条警告后忽略它。

警告与错误不同。警告不中断运行，错误会中断运行。

配置错误退出码为 1。参数错误退出码也为 1。运行阶段异常退出码为 2。成功结束退出码为 0。

双击运行时，程序出错后会等待用户按回车键，便于看清提示。加 `--no-pause` 可以跳过等待。

配置在日志初始化之前读取。所以启动最早期的警告和错误只显示在控制台，不会写入日志文件。

### 1.3 JSON 书写规则

- 文件编码使用 UTF-8。
- 字符串必须用英文双引号包裹。
- JSON 不支持注释，也不支持末尾多余逗号。
- 布尔值写小写 `true` 或 `false`。
- 数字不加引号，`20` 是数字，`"20"` 是字符串。
- 对象用花括号，数组用方括号。
- 键名区分大小写，必须与本文一致。
- 模式名与地形名不区分大小写，例如 `1v1` 与 `1V1` 等价，`mountain` 与 `Mountain` 等价。

### 1.4 比赛、局、回合的叫法

为避免混淆，本文与代码统一使用下面的叫法。

- 回合：一局内的一次集体移动，对应 `game.maxTurns` 计数的单位。
- 局：一次完整的对局，从生成地图开始，到只剩一支队伍或到达最大回合数结束。
- 比赛：由一场或多场局组成。一场比赛包含多少局由 `game.gamesPerMatch` 决定。

计分按局累计。一场比赛的所有局结束后打印该场比赛的累计排名。全部比赛结束后打印最终排名。

## 二、map 段：地图

`map` 段控制地图尺寸、地形、随机种子与中立城市兵力。

```json
"map": {
    "rows": 20,
    "cols": 20,
    "bannedTerrains": [],
    "seed": 0,
    "cityProbability": 0.06,
    "mountainProbability": 0.15,
    "swampProbability": 0.03,
    "cityUnitsMin": 30,
    "cityUnitsMax": 55
}
```

### map.rows

- 类型：整数
- 默认值：20
- 取值范围：5 到 200
- 作用：地图行数，也就是地图竖直方向的格子数量。坐标 $(x, y)$ 中 $x$ 对应行。
- 示例：`"rows": 24`

### map.cols

- 类型：整数
- 默认值：20
- 取值范围：5 到 200
- 作用：地图列数，也就是地图水平方向的格子数量。坐标 $(x, y)$ 中 $y$ 对应列。
- 示例：`"cols": 24`

### map.bannedTerrains

- 类型：字符串数组
- 默认值：`[]`，表示不禁用任何地形
- 取值范围：数组元素只能是下列地形英文名之一，不区分大小写。
    - `blank` 空地
    - `mountain` 山区
    - `swamp` 沼泽
    - `city` 城市
    - `capital` 首都
- 作用：禁用地形。被禁用的地形不会在地图上生成。禁用后该地形概率权重清零，其余地形按比例重新归一化。概率之和的校验与禁用无关，仍然要满足不超过 1。
- 限制：`blank` 与 `capital` 是必需地形，不允许禁用。写成这两个值会报配置错误。
- 示例：`"bannedTerrains": ["mountain", "swamp"]`

### map.seed

- 类型：整数
- 默认值：0
- 取值范围：0 到 4294967295
- 作用：地图生成与随机分配的随机种子。0 表示每次运行都随机。写成非 0 值时，同一种子会得到相同的地图与相同的随机结果，便于复现问题。命令行参数 `--seed` 优先于本键。
- 示例：`"seed": 20240915`

### map.cityProbability

- 类型：数字
- 默认值：0.06
- 取值范围：0 到 1，含两端
- 作用：每个格子生成城市的概率权重。中立城市初始兵力在 `cityUnitsMin` 到 `cityUnitsMax` 之间随机。
- 示例：`"cityProbability": 0.08`

### map.mountainProbability

- 类型：数字
- 默认值：0.15
- 取值范围：0 到 1，含两端
- 作用：每个格子生成山区的概率权重。山区不能驻扎兵力，也不能通行。
- 示例：`"mountainProbability": 0.18`

### map.swampProbability

- 类型：数字
- 默认值：0.03
- 取值范围：0 到 1，含两端
- 作用：每个格子生成沼泽的概率权重。被占领的沼泽每回合减少 1 个兵力，最少减到 1。
- 示例：`"swampProbability": 0.04`

`cityProbability` `mountainProbability` `swampProbability` 三者之和不得超过 1。校验不通过时报配置错误。

空地概率为剩余部分 $1 - p_{city} - p_{mountain} - p_{swamp}$。若还禁用了某类地形，该类地形权重清零，剩余地形按比例重新归一化。

### map.cityUnitsMin

- 类型：整数
- 默认值：30
- 取值范围：1 到 100000
- 作用：中立城市初始兵力的下界，含本数。
- 示例：`"cityUnitsMin": 40`

### map.cityUnitsMax

- 类型：整数
- 默认值：55
- 取值范围：1 到 100000
- 作用：中立城市初始兵力的上界，含本数。必须不小于 `cityUnitsMin`。
- 示例：`"cityUnitsMax": 60`

## 三、game 段：对局

`game` 段控制游戏模式、回合数、局数、时限与违规判定。

```json
"game": {
    "mode": "1v1",
    "maxTurns": 1500,
    "gamesPerMatch": 1,
    "ffaPlayerCount": 4,
    "initTimeLimitMs": 2000,
    "turnTimeLimitMs": 50,
    "maxViolations": 5
}
```

### game.mode

- 类型：字符串
- 默认值：`"1v1"`
- 取值范围：`1v1` `2v2` `ffa`，不区分大小写
- 作用：游戏模式。
    - `1v1`：2 名玩家，2 支队伍，每队 1 人。
    - `2v2`：4 名玩家，2 支队伍，每队 2 人。
    - `ffa`：混战，每名玩家一支队伍，玩家数由 `game.ffaPlayerCount` 决定。
- 示例：`"mode": "2v2"`

### game.maxTurns

- 类型：整数
- 默认值：1500
- 取值范围：1 到 1000000
- 作用：一局的最大回合数。到达最大回合数仍未只剩一支队伍时，按队伍排名与兵力排名结算。
- 示例：`"maxTurns": 800`

### game.gamesPerMatch

- 类型：整数
- 默认值：1
- 取值范围：1 到 1000
- 作用：一场比赛包含多少局。每个玩家组合进行一场比赛，每场比赛依次进行这么多局，每局独立生成地图并累计计分。
- 示例：`"gamesPerMatch": 3`

### game.ffaPlayerCount

- 类型：整数
- 默认值：4
- 取值范围：2 到 16
- 作用：FFA 模式的玩家数。只在 `game.mode` 为 `ffa` 时生效。FFA 中每名玩家一支队伍，所以它同时也是队伍数。1v1 固定 2 名玩家，2v2 固定 4 名玩家，其他模式下本键被忽略。
- 示例：`"ffaPlayerCount": 6`

### game.initTimeLimitMs

- 类型：整数
- 默认值：2000
- 取值范围：1 到 60000，单位毫秒
- 作用：初始化时限。从游戏程序发送完 `INIT` 帧开始计时，到收到 AI 程序输出的 `READY` 行为止。超时或输出不是 `READY` 的玩家判负。
- 示例：`"initTimeLimitMs": 3000`

### game.turnTimeLimitMs

- 类型：整数
- 默认值：50
- 取值范围：1 到 60000，单位毫秒
- 作用：每回合时限。从游戏程序发送完 `GO` 帧开始计时，到收到完整动作行为止。超时按 PASS 处理，并记一次违规。
- 示例：`"turnTimeLimitMs": 100`

### game.maxViolations

- 类型：整数
- 默认值：5
- 取值范围：0 到 1000
- 作用：连续违规次数上限。单次超时或非法输出按 PASS 处理并记一次违规。连续违规次数达到上限的玩家判负。写成 0 表示不因违规判负。合法操作或 PASS 会把连续违规计数清零。初始化失败、进程崩溃、输出结束仍直接判负。
- 示例：`"maxViolations": 3`

## 四、match 段：比赛与计分

`match` 段控制比赛方式、参赛队伍与计分权重。

```json
"match": {
    "autoMatch": false,
    "teams": [["example"], ["demo_expand"]],
    "playerWeight": 1.0,
    "teamWeight": 0.0
}
```

### match.autoMatch

- 类型：布尔
- 默认值：`false`
- 取值范围：`true` 或 `false`
- 作用：自动匹配开关。
    - `true`：忽略 `match.teams`，枚举 `battle/` 下全部可用玩家，按当前模式所需人数取出全部玩家组合，每个组合进行一场比赛，每场比赛包含 `gamesPerMatch` 局。每局开始前随机分配队伍。
    - `false`：只进行一场比赛，参赛玩家与队伍由 `match.teams` 指定，每局队伍不变。
- 示例：`"autoMatch": true`

### match.teams

- 类型：数组的数组，内层元素为字符串
- 默认值：`[]`
- 取值范围：二维字符串数组，外层每项是一支队伍，内层是玩家 id。队伍数量与每队人数必须与 `game.mode` 匹配，见下面限制。
- 作用：显式队伍配置。外层数组的每一项是一支队伍，内层数组是这支队伍的玩家 id。
- 限制：`autoMatch` 为 `false` 时必须显式配置，并且与模式匹配。
    - `1v1`：2 支队伍，每队 1 人。
    - `2v2`：2 支队伍，每队 2 人。
    - `ffa`：共 `ffaPlayerCount` 支队伍，每队 1 人。
- 玩家 id 规则：只允许大小写英文字母、数字、下划线、短横线。长度 1 到 64。同一玩家在所有队伍中只能出现一次。
- 玩家可用性：每个玩家 id 必须对应 `battle/<id>/<id>.exe`。配置格式合法但可执行文件不存在时，启动阶段报错。
- 示例：`"teams": [["example", "demo_expand"], ["demo_random", "demo_rush"]]`

### match.playerWeight

- 类型：数字
- 默认值：1.0
- 取值范围：不小于 0
- 作用：玩家分权重。参与每局计分公式。
- 示例：`"playerWeight": 0.2`

### match.teamWeight

- 类型：数字
- 默认值：0.0
- 取值范围：不小于 0
- 作用：队伍分权重。参与每局计分公式。1v1 与 FFA 中队伍与玩家一一对应，队伍分与玩家分相同，一般设为 0。2v2 建议玩家权重 0.2、队伍权重 0.8。
- 示例：`"teamWeight": 0.8`

### 自动匹配与显式队伍的关系

两种比赛方式互斥，由 `match.autoMatch` 选择。

- 自动匹配开启时，`match.teams` 被忽略。若 `match.teams` 非空，程序会写警告提示它被忽略。
- 自动匹配关闭时，必须写 `match.teams`。程序只运行一场比赛。
- 自动匹配需要 `battle/` 下至少有当前模式所需人数的可用玩家。人数不足时启动失败，并提示需要的玩家数与实际可用玩家数。
- 自动匹配的组合数会随玩家数快速增长。玩家数量超过 300 时程序拒绝运行。组合数超过 2000 时会写警告，提示运行时间可能较长。
- 以 `battle/` 下有 4 名可用玩家、模式为 1v1 为例，自动匹配会生成 $\binom{4}{2} = 6$ 场比赛，每场 `gamesPerMatch` 局。

显式队伍配置只影响比赛安排，不影响玩家可执行文件的扫描。`battle/` 中未被引用的玩家目录会被忽略。

### 计分方式与权重公式

每局结束后按名次给玩家分与队伍分，再按权重加权累计到玩家总分。

符号含义如下。

| 符号 | 含义 |
| --- | --- |
| $N_{p}$ | 本局玩家总数 |
| $R_{p}$ | 玩家本局名次，从 1 开始，1 为第一名 |
| $N_{t}$ | 本局队伍总数 |
| $R_{t}$ | 玩家所属队伍本局名次，从 1 开始，1 为第一名 |
| $w_{p}$ | `match.playerWeight` 玩家权重 |
| $w_{t}$ | `match.teamWeight` 队伍权重 |

每局玩家分与队伍分：

$$S_{p} = N_{p} - R_{p} + 1$$

$$S_{t} = N_{t} - R_{t} + 1$$

每局加权得分：

$$S = w_{p} \cdot S_{p} + w_{t} \cdot S_{t}$$

一名玩家参加 $G$ 局后的总分：

$$S_{\text{total}} = \sum_{g=1}^{G} S_{g}$$

说明如下。

- 名次越靠前得分越高。最后一名得 1 分。
- 总分按局累加。一场比赛有 `gamesPerMatch` 局，自动匹配有若干场比赛，全部对局都计入总分。
- 两个权重都为 0 时总分恒为 0。程序会写警告提示。
- 1v1 与 FFA 中队伍分与玩家分相同，权重一般设为玩家 1.0、队伍 0.0。
- 2v2 推荐玩家权重 0.2、队伍权重 0.8。两名同队玩家队伍分相同，玩家分按个人名次区分。
- 累计排名打印到控制台与 `logs/score.log`。每场比赛结束后打印一次，全部比赛结束后打印最终排名。

## 五、ui 段：界面

`ui` 段控制图形界面显示。

```json
"ui": {
    "enabled": true,
    "cellSize": 36,
    "turnDelayMs": 30,
    "resultDelayMs": 1200
}
```

### ui.enabled

- 类型：布尔
- 默认值：`true`
- 取值范围：`true` 或 `false`
- 作用：是否显示图形界面。命令行参数 `--no-ui` 也会关闭界面。两者都允许时才显示界面。关闭界面后不创建窗口，适合批量运行与自动测试。
- 示例：`"enabled": false`

### ui.cellSize

- 类型：整数
- 默认值：36
- 取值范围：8 到 128，单位像素
- 作用：每个地图格子的边长。它决定窗口大小，格子越大窗口越大。
- 示例：`"cellSize": 48`

### ui.turnDelayMs

- 类型：整数
- 默认值：30
- 取值范围：0 到 60000，单位毫秒
- 作用：界面模式下每回合画面停留时间。值越大播放越慢，便于观察。界面打开时也可以用界面按键临时加快或减慢。当前界面实现的播放间隔上限为 500 毫秒，配置值更大时按 500 毫秒播放。无界面模式下本键被忽略。
- 示例：`"turnDelayMs": 100`

### ui.resultDelayMs

- 类型：整数
- 默认值：1200
- 取值范围：0 到 60000，单位毫秒
- 作用：一局结束后终局画面的停留时间。值越大越容易看清排名。无界面模式下本键被忽略。
- 示例：`"resultDelayMs": 2000`

## 六、log 段：日志

`log` 段控制日志目录与操作记录。

```json
"log": {
    "directory": "logs",
    "recordMoves": true
}
```

### log.directory

- 类型：字符串
- 默认值：`"logs"`
- 取值范围：不能为空字符串
- 作用：日志目录。目录不存在时自动创建。目录无法创建时启动失败。
    - 主日志写入 `<目录>/serve.log`。
    - 累计计分写入 `<目录>/score.log`。
    - 开启操作记录时，每局操作记录写入 `<目录>/moves/`。
    - AI 程序的标准错误输出写入 `<目录>/ai/`。
- 示例：`"directory": "logs/2v2"`

### log.recordMoves

- 类型：布尔
- 默认值：`true`
- 取值范围：`true` 或 `false`
- 作用：是否记录玩家操作与地图修改。开启时每局写一个可读文本文件，记录每回合玩家的动作与地图变化，便于回看与排查问题。关闭后不写这些文件，节省磁盘空间。
- 示例：`"recordMoves": false`

## 七、预设配置说明

仓库在 `config/` 下提供 5 份预设配置。全部预设都需要先运行 `build.bat` 构建 `serve.exe` 与示例玩家。

四名示例玩家分别是 `example` `demo_expand` `demo_random` `demo_rush`。每名玩家必须存在 `battle/<id>/<id>.exe`。

### config/example.json

- 用途：默认配置，也是配置示例。第一次运行与构建验证使用这份配置。
- 模式：`1v1`，显式队伍。
- 玩家：`example` 与 `demo_expand`，各一支队伍。
- 权重：玩家 1.0，队伍 0.0。
- 运行：

```text
serve.exe --config config\example.json
```

### config/1v1.json

- 用途：1v1 对战预设，换一个对手。
- 模式：`1v1`，显式队伍。
- 玩家：`example` 与 `demo_random`，各一支队伍。
- 权重：玩家 1.0，队伍 0.0。
- 运行：

```text
serve.exe --config config\1v1.json
```

### config/2v2.json

- 用途：2v2 团队对战预设，演示队伍与权重。
- 模式：`2v2`，显式队伍。
- 队伍：`example` 与 `demo_expand` 一队，`demo_random` 与 `demo_rush` 一队。
- 权重：玩家 0.2，队伍 0.8。
- 运行：

```text
serve.exe --config config\2v2.json
```

### config/ffa.json

- 用途：FFA 混战预设。
- 模式：`ffa`，`ffaPlayerCount` 为 4。
- 玩家：`example` `demo_expand` `demo_random` `demo_rush` 各一支队伍。
- 权重：玩家 1.0，队伍 0.0。
- 运行：

```text
serve.exe --config config\ffa.json
```

### config/auto.json

- 用途：自动匹配预设。
- 模式：`1v1`，`autoMatch` 为 `true`。
- 队伍：`match.teams` 为空数组，自动匹配时被忽略。
- 权重：玩家 1.0，队伍 0.0。
- 运行：

```text
serve.exe --config config\auto.json --no-ui
```

`battle/` 下有 4 名可用玩家时，这份配置会生成 6 场 1v1 比赛，每场 1 局。

## 八、完整配置示例

下面是完整可运行的配置，内容与 `config/example.json` 一致，包含全部 26 个键。

```json
{
    "map": {
        "rows": 20,
        "cols": 20,
        "bannedTerrains": [],
        "seed": 0,
        "cityProbability": 0.06,
        "mountainProbability": 0.15,
        "swampProbability": 0.03,
        "cityUnitsMin": 30,
        "cityUnitsMax": 55
    },
    "game": {
        "mode": "1v1",
        "maxTurns": 1500,
        "gamesPerMatch": 1,
        "ffaPlayerCount": 4,
        "initTimeLimitMs": 2000,
        "turnTimeLimitMs": 50,
        "maxViolations": 5
    },
    "match": {
        "autoMatch": false,
        "teams": [["example"], ["demo_expand"]],
        "playerWeight": 1.0,
        "teamWeight": 0.0
    },
    "ui": {
        "enabled": true,
        "cellSize": 36,
        "turnDelayMs": 30,
        "resultDelayMs": 1200
    },
    "log": {
        "directory": "logs",
        "recordMoves": true
    }
}
```

这段 JSON 可以直接保存为 `config/my.json` 后运行。

## 九、自己修改配置

### 9.1 修改步骤

1. 从 `config/example.json` 复制一份，例如复制为 `config/my.json`。
2. 用支持 UTF-8 的编辑器打开，例如 VS Code 或记事本。
3. 按需修改键值，建议保留全部键，不要随意删除。
4. 保存文件，确认没有语法错误。
5. 运行 `serve.exe --config config\my.json`。
6. 若报配置错误，按提示中的键路径与当前值修改。

也可以直接修改预设文件。但预设文件被其他测试或文档引用，建议新建文件，不要覆盖预设。

### 9.2 JSON 语法注意

- 每个键值对之间用英文逗号分隔，最后一个键值对后面不要加逗号。
- 字符串用英文双引号，不要用中文引号。
- 不要写注释。
- 布尔值写 `true` 或 `false`，不要写成 `"true"` 或 `是`。
- 数字不要加引号。
- 中文内容可以写在字符串里，例如玩家 id 只允许英文与数字，但日志目录可以含中文。

### 9.3 常见修改对照

| 想做什么 | 修改哪个键 |
| --- | --- |
| 改地图大小 | `map.rows` 与 `map.cols` |
| 缩短一局时间 | 减小 `game.maxTurns` |
| 多打几局再排名 | 增大 `game.gamesPerMatch` |
| 禁用山区 | `map.bannedTerrains` 写 `["mountain"]` |
| 增加城市数量 | 增大 `map.cityProbability`，并保证三者之和不超过 1 |
| 放宽每回合时限 | 增大 `game.turnTimeLimitMs` |
| 换成 2v2 | `game.mode` 写 `"2v2"`，`match.teams` 写两队各两人 |
| 换成 FFA | `game.mode` 写 `"ffa"`，设置 `ffaPlayerCount`，`match.teams` 写对应数量的队伍 |
| 开启自动匹配 | `match.autoMatch` 写 `true`，`match.teams` 写空数组 |
| 关闭图形界面 | `ui.enabled` 写 `false`，或加命令行参数 `--no-ui` |
| 关闭操作记录 | `log.recordMoves` 写 `false` |
| 换日志目录 | 修改 `log.directory` |
| 复现某次随机地图 | 设置 `map.seed` 为非 0 值，或使用 `--seed` 参数 |
| 调整 2v2 计分侧重 | 修改 `match.playerWeight` 与 `match.teamWeight` |

## 十、常见配置错误提示

程序在标准错误输出中文提示。以下按提示关键字说明含义与处理方法。

### 10.1 配置错误

配置错误会中断启动，退出码为 1。

| 错误提示关键字 | 含义 | 处理方法 |
| --- | --- | --- |
| `配置文件不存在` | 路径写错或文件被删除 | 检查 `--config` 后面的路径，确认文件存在 |
| `解析配置文件 ... 失败 第 X 行 第 Y 列` | JSON 语法错误，行列从 1 开始 | 按行列位置检查括号、逗号、引号 |
| `根节点必须是对象` | 文件最外层不是花括号对象 | 用 `{` 与 `}` 包住整份配置 |
| `配置键 ... 必须是整数` | 该键收到字符串或小数 | 去掉引号，只写整数 |
| `配置键 ... 必须是数字` | 该键收到字符串或其他类型 | 概率与权重直接写数字 |
| `配置键 ... 必须是布尔值` | 该键收到字符串或数字 | 写 `true` 或 `false` |
| `配置键 ... 必须是字符串` | 该键收到数字或数组 | 加英文双引号 |
| `配置键 ... 必须是数组` | 该键收到对象或数字 | 用方括号写数组 |
| `配置键 ... 必须是对象` | 某个配置段不是花括号对象 | 检查段名后的值 |
| `配置键 map.rows 必须是 5 到 200 的整数 当前为 3` | 取值越界，提示给出允许范围与当前值 | 改成范围内的整数 |
| `配置键 map.seed 必须是 0 到 4294967295 的整数` | 随机种子越界 | 改成范围内的整数 |
| `配置键 game.mode 的取值 3v3 非法` | 模式名未知 | 写 `1v1`、`2v2` 或 `ffa` |
| `配置键 map.bannedTerrains[0] 的地形名 volcano 非法` | 地形名未知 | 只能写 `blank`、`mountain`、`swamp`、`city`、`capital` |
| `配置键 map.bannedTerrains[0] 不允许禁用空地 blank` | 禁用了必需地形 | 从数组中删除 `blank` 与 `capital` |
| `配置键 map.cityProbability map.mountainProbability map.swampProbability 之和不能超过 1` | 三个概率之和超过 1 | 调低至少一个概率 |
| `配置键 map.cityUnitsMin 不能大于 map.cityUnitsMax` | 城市兵力下界大于上界 | 调换或修改两个值，保证下界不大于上界 |
| `配置键 match.playerWeight 不能小于 0` | 权重为负数 | 改成不小于 0 的数 |
| `配置键 match.teamWeight 不能小于 0` | 权重为负数 | 改成不小于 0 的数 |
| `配置键 match.teams 不能为空 未开启自动匹配时必须显式配置队伍` | 关闭自动匹配但没有写队伍 | 补全队伍，或改成自动匹配 |
| `配置键 match.teams[1][0] 的玩家 id example 重复` | 同一玩家出现在两支队伍 | 每名玩家只出现一次 |
| `配置键 match.teams[1][0] 的玩家 id bad name 非法` | 玩家 id 含空格或非法字符 | 只用字母、数字、下划线、短横线 |
| `配置键 match.teams 在 1v1 模式下必须是 2 支队伍 当前为 3 支` | 队伍数量与模式不符 | 按模式调整队伍数量 |
| `配置键 match.teams[0] 在 2v2 模式下必须包含 2 名玩家 当前为 1 名` | 每队人数与模式不符 | 2v2 每队写 2 人 |
| `配置键 ui.cellSize 必须是 8 到 128 的整数` | 格子边长越界 | 改成范围内的整数 |
| `配置键 log.directory 不能为空` | 日志目录写成空字符串 | 写一个目录名，例如 `"logs"` |

### 10.2 配置警告

警告不中断运行。

| 警告提示关键字 | 含义 | 处理方法 |
| --- | --- | --- |
| `配置缺少配置段 map 该段全部使用默认值` | 整个段缺失 | 补全该段，或确认默认值适用 |
| `配置键 map.rows 缺失 使用默认值 20` | 单个键缺失 | 补上该键 |
| `配置段 map 中存在未知键 xxx 已忽略` | 键名写错或多余 | 核对本文键名，删除多余键 |
| `配置键 match.teams 在开启自动匹配时会被忽略` | 自动匹配与显式队伍同时配置 | 清空 `match.teams` 或关闭自动匹配 |
| `配置键 match.playerWeight 与 match.teamWeight 之和为 0` | 两个权重都为 0，总分恒为 0 | 至少设置一个大于 0 的权重 |

### 10.3 运行阶段与配置相关的错误

配置本身合法，但运行环境或玩家文件不满足要求时，启动阶段会报错。这类错误同样退出码为 1。

| 错误提示关键字 | 含义 | 处理方法 |
| --- | --- | --- |
| `找不到 battle 目录` | 没有 `battle/` 目录 | 在仓库根目录运行程序，或先运行 `build.bat` |
| `battle 目录下没有可用玩家` | 玩家目录为空或缺少可执行文件 | 先运行 `build.bat` 构建示例玩家 |
| `自动匹配需要 N 名玩家 但 battle 目录只有 M 名可用玩家` | 可用玩家数不足 | 构建更多玩家，或关闭自动匹配 |
| `队伍配置引用的玩家不可用 xxx` | 显式队伍里的玩家没有可执行文件 | 检查 `battle/<id>/<id>.exe` 是否存在 |
| `无法创建日志目录` | `log.directory` 不可写 | 换一个可写目录，或检查权限 |
| `无法初始化日志` | 日志文件无法打开 | 同上 |
| `玩家 xxx 启动失败` | AI 可执行文件无法启动 | 检查玩家可执行文件是否可运行 |
| `玩家 xxx 判负` | AI 超时、崩溃、非法输出或初始化失败 | 查看 `logs/` 下对应日志与 `logs/ai/` 标准错误 |
