阅读顺序建议：

1. 先读 [README](../README.md)。了解项目是什么，怎么构建，怎么运行。
2. 再读本文。了解代码结构。
3. 写 AI 的读者读 [选手须知](../选手须知.md)。
4. 改配置的读者读 [配置说明](配置说明.md)。
5. 配环境的读者读 [构建与环境](构建与环境.md)。
6. 跑测试的读者读 [测试说明](测试说明.md)。
7. 想了解游戏规则的读者读 [generals.io游戏规则](../generals.io游戏规则.md)。

本文中的公式使用 LaTeX 写法。行内公式用 `$` 包裹，行间公式用 `$$` 包裹。

## 二 模块总览

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 程序入口 | `src/main.cpp` | 解析命令行、读配置、初始化日志、启动总编排、处理退出码 |
| 配置 | `src/core/config.*` | 读取 JSON、补默认值、校验取值、生成配置说明文字 |
| 公共类型 | `src/include/type.hpp` | 地形枚举、可见地形枚举、坐标、排名 |
| 地图 | `src/include/map.hpp` | 二维格子容器 |
| 方向 | `src/include/direction.hpp` | 上下左右方向常量 |
| 工具 | `src/include/util.hpp` | 坐标运算、距离、数值裁剪 |
| 随机 | `src/include/random.hpp` | 全局随机数生成器、种子控制 |
| 日志 | `src/include/logger.hpp` | 线程安全日志对象 |
| JSON | `src/include/json.hpp` | 单头文件 JSON 解析器 |
| 句柄 | `src/include/unique_handle.hpp` | RAII 管理 Windows 句柄 |
| 玩家 | `src/core/player.*` | 玩家、队伍、注册表 |
| 规则 | `src/core/rule.*` | 移动校验、移动执行、兵力生成、淘汰 |
| 游戏 | `src/core/game.*` | 一局状态、回合推进、视野、排名 |
| 地图生成 | `src/core/map_generator.*` | 随机地形、放置首都、保证连通 |
| 计分 | `src/core/score.*` | 加权累计总分与排名 |
| 操作记录 | `src/core/recorder.*` | 写人类可读的操作记录 |
| 通信通道 | `src/io/io.*` | 启动 AI 进程、管道读写、超时与异常 |
| 协议 | `src/io/protocol.*` | 把游戏状态编码为字节消息 |
| 界面 | `src/ui/ui.*` | EasyX 窗口、地图绘制、按键处理 |
| 总编排 | `src/core/runner.*` | 发现玩家、组织比赛、逐局运行、汇总排名 |

模块调用关系：

```text
main
  -> Runner
       -> Config
       -> Game
            -> Rule
            -> MapGenerator
            -> PlayerRegistry
       -> AIChannel
            -> protocol
       -> MoveRecorder
       -> ScoreBoard
       -> Renderer
```

## 三 文件夹说明

### 3.1 `src/`

源代码目录。全部实现代码在这里。

命名空间按头文件实际声明为准。`include/` 下的文件不要求使用同一个命名空间。

- `gen`：基础类型与工具。包括 `type.hpp`、`direction.hpp`、`util.hpp`、`random.hpp`、`logger.hpp`、`json.hpp`、`unique_handle.hpp`、`move_operation.hpp`。
- `gen::core`：核心游戏类型与逻辑。包括 `map.hpp` 的 `Tile` 与 `GameMap`，以及 `config.hpp`、`player.hpp`、`rule.hpp`、`game.hpp`、`map_generator.hpp`、`score.hpp`、`recorder.hpp`、`runner.hpp`。
- `gen::io`：通信。其中协议编码使用 `gen::io::protocol`。
- `gen::ui`：界面。

新增代码时按所在目录和已有头文件的命名空间选择，不要随意改动已有声明。

`src` 下只有一个 `main.cpp`，其余按模块分到三个子目录。

### 3.2 `src/include/`

公共头文件目录。存放跨模块使用的类型和工具。这里的文件大多是头文件实现，只有声明和内联函数。

存放内容：

- 基础类型与枚举。
- 地图容器。
- 方向、坐标、距离工具。
- 随机数。
- 日志。
- JSON 解析。
- Windows 句柄包装。
- 移动操作结构体。

`include/` 下的文件不需要单独编译。它们被其他 `.cpp` 包含。

### 3.3 `src/core/`

核心游戏逻辑目录。存放配置、玩家、规则、游戏、地图生成、计分、操作记录和总编排。

存放内容：

- `config.hpp`、`config.cpp`：配置结构与读取校验。
- `player.hpp`、`player.cpp`：玩家、队伍、注册表。
- `rule.hpp`、`rule.cpp`：规则判定与执行。
- `game.hpp`、`game.cpp`：一局游戏的完整状态与流程。
- `map_generator.hpp`、`map_generator.cpp`：地图生成。
- `score.hpp`、`score.cpp`：计分板。
- `recorder.hpp`、`recorder.cpp`：操作记录。
- `runner.hpp`、`runner.cpp`：程序总编排。
- `main.cpp` 不在这里，放在 `src/` 根目录。

### 3.4 `src/io/`

通信目录。负责服务器与玩家 AI 之间的进程和管道交互。

存放内容：

- `io.hpp`、`io.cpp`：通信通道抽象类、Windows 管道实现、AI 进程启动、动作读取。
- `protocol.hpp`、`protocol.cpp`：消息类型常量、小端序编码函数、各类消息负载构造。

协议规范文本放在 [选手须知](../选手须知.md) 的通信协议一节。

### 3.5 `src/ui/`

图形界面目录。使用 EasyX 绘制游戏画面。

存放内容：

- `ui.hpp`：绘制数据结构与 `Renderer` 静态接口。
- `ui.cpp`：EasyX 窗口、网格、地形、兵力、排名、按键处理。

### 3.6 `lib/`

外部库目录。全部外部依赖放在这里，并且必须能静态链接。

存放内容：

- `lib/easyx/`：EasyX 图形库。
- `lib/magic_enum/`：magic_enum 枚举反射库。

这两个库都不需要运行时动态库。

### 3.7 `lib/easyx/`

EasyX 图形库。用于绘制窗口。

包含文件：

| 文件 | 说明 |
| --- | --- |
| `easyx.h` | EasyX 主头文件 |
| `graphics.h` | 图形接口头文件，兼容 TC 图形库写法 |
| `lib/libeasyx.a` | EasyX 静态链接库 |

使用方式：编译时加 `-Ilib`，链接时加 `-Llib/easyx/lib -leasyx`，并补充 Windows 系统库 `-lgdi32 -lole32 -lwinmm -lgdiplus`。

官方网站：<https://easyx.cn>

EasyX 以静态库形式提供。运行程序时不需要额外的 EasyX DLL。

### 3.8 `lib/magic_enum/`

magic_enum 枚举反射库。用于把枚举转换成名字，以及从名字解析枚举值。

包含文件：

| 文件 | 说明 |
| --- | --- |
| `magic_enum.hpp` | 主头文件 |
| `magic_enum_all.hpp` | 全部功能汇总头文件 |
| `magic_enum_containers.hpp` | 容器支持 |
| `magic_enum_flags.hpp` | 位标志支持 |
| `magic_enum_format.hpp` | 格式化支持 |
| `magic_enum_fuse.hpp` | 融合支持 |
| `magic_enum_iostream.hpp` | 输入输出流支持 |
| `magic_enum_switch.hpp` | 分支支持 |
| `magic_enum_utility.hpp` | 工具函数 |

GitHub 仓库：<https://github.com/Neargye/magic_enum>

magic_enum 是纯头文件库。编译时包含即可，不需要链接 `.a` 或 `.lib`，也不需要运行时 DLL。

### 3.9 `assets/`

游戏资源目录。用于放图片、字体等资源。

当前为空。如果以后新增资源，要在这里说明用途和使用位置。

### 3.10 `battle/`

玩家 AI 目录。每个玩家一个子目录，结构为 `battle/<id>/<id>.exe`。

存放内容：

- 玩家源代码。
- 玩家构建脚本。
- 玩家可执行文件。
- 玩家说明文档。

自带的玩家：

| 目录 | 说明 |
| --- | --- |
| `battle/example/` | 示例 AI，注释最完整，适合入门参考 |
| `battle/demo_expand/` | 演示玩家，偏扩张 |
| `battle/demo_random/` | 演示玩家，随机动作 |
| `battle/demo_rush/` | 演示玩家，偏快攻 |

具体玩家以实际目录为准。`build.bat` 会尝试构建这四个玩家。

规则：

- `id` 只能包含大小写英文字母、数字、下划线、短横线。
- `id` 长度 1 到 64。
- 文件夹名与可执行文件名必须一致。
- 服务器运行玩家程序时，工作目录为 `battle/<id>`。
- 玩家目录里可以放 `icon.png` 作为界面底图，要求正方形。没有时使用纯色底图。

### 3.11 `config/`

配置文件目录。全部配置使用 JSON。

存放内容：

| 文件 | 说明 |
| --- | --- |
| `example.json` | 默认配置，展示全部键 |
| `1v1.json` | 1v1 预设 |
| `2v2.json` | 2v2 预设 |

`config` 下只有上面这五份预设配置。没有其他配置文件。

配置键的详细说明见 [配置说明](配置说明.md)。

### 3.12 `doc/`

开发文档目录。

存放内容：

- `文档.md`：本文，开发文档索引。
- [配置说明.md](配置说明.md)：配置写法说明。
- [构建与环境.md](构建与环境.md)：环境安装与构建说明。
- [测试说明.md](测试说明.md)：测试方案说明。

### 3.13 `logs/`

运行日志目录。由程序生成，通常不提交到 git。

存放内容：

- `serve.log`：主日志。
- `score.log`：累计排名日志。
- `moves/`：每局操作记录。
- `ai/`：玩家 AI 的标准错误输出。

日志目录不存在时，程序会自动创建。目录可在 `log.directory` 配置。

### 3.14 `tests/`

测试目录。存放自动测试脚本和测试用 AI。

存放内容：

- `run_tests.ps1`：验收测试脚本。兼容 Windows 自带的 Windows PowerShell 5.1，脚本编码为 UTF-8 BOM。
- `README.md`：测试目录的简要说明。
- `ai/`：测试用 AI 源码和辅助头文件。
  - `timeout_ai.cpp`：故意超时的 AI。
  - `crash_ai.cpp`：收到回合消息后退出并返回非零退出码的 AI。
  - `invalid_ai.cpp`：输出非协议文本的 AI。
  - `illegal_move_ai.cpp`：输出格式合法但棋盘上非法的移动的 AI。
  - `protocol_util.hpp`：测试 AI 共用的读帧、写行工具。

测试脚本用 `--no-ui` 模式跑全部测试，结果写到 `build/test_output/`。汇总报告是 `build/test_output/report.md`。项目约定的归档位置是 `LLM_notice/测试报告.md`，验收结束后人工归档。

开发过程记录目录。存放任务说明、开发计划、测试报告等。

## 四 `src` 文件逐个说明

### 4.1 `src/main.cpp`

作用：程序入口。负责参数解析、配置读取、日志初始化、启动总编排。

主要流程：

1. 设置控制台代码页为 UTF-8。
2. 设置窗口标题。
3. 解析命令行参数。
4. 读取配置。配置错误时打印中文信息，退出码为 1。
5. 初始化日志。失败时打印提示，退出码为 1。
6. 创建 `Runner` 并运行。
7. 记录退出码并关闭日志。
8. 出错时按需暂停，避免双击运行时窗口一闪而过。

命令行参数：

| 参数 | 作用 |
| --- | --- |
| `--config <路径>` 或 `-c <路径>` | 指定配置文件 |
| `--no-ui` | 不显示图形界面 |
| `--seed <数字>` | 指定随机种子 |
| `--no-pause` | 出错时不等待按键 |
| `--help` 或 `-h` | 显示帮助 |

退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 正常结束或显示帮助 |
| 1 | 参数错误、配置错误、日志初始化失败 |
| 2 | 运行中抛出异常 |

内部函数说明：

- `showHelp()`：打印帮助文本，无参数，无返回值。
- `isInteractiveConsole()`：判断当前是否有可用控制台。无参数。返回 `bool`，有控制台为 `true`。
- `pauseIfNeeded(bool pause)`：出错时等待回车。参数 `pause` 为是否允许暂停。无返回值。
- `parseArguments(int argc, char **argv, RunOptions &options, bool &pauseOnError)`：解析参数。参数 `argc`、`argv` 为命令行参数，`options` 为输出参数，`pauseOnError` 为输出参数。返回 `int`，0 表示成功，1 表示显示帮助，2 表示参数错误。

### 4.2 `src/include/type.hpp`

作用：通用类型。包括地形、可见地形、坐标、排名。

命名空间：`gen`。

公开枚举：

- `enum class Terrain : int`：真实地形。取值 `Blank = 0`、`Mountain = 1`、`Swamp = 2`、`City = 3`、`Capital = 4`。
- `enum class VisibleTerrain : int`：可见地形。取值 0 到 4 同真实地形，`FogBlank = 5`、`FogMountain = 6`、`FogSwamp = 7`。

公开常量：

- `inline constexpr int TERRAIN_COUNT = 5`：真实地形数量。
- `inline constexpr int VISIBLE_TERRAIN_COUNT = 8`：可见地形数量。

公开函数：

| 函数 | 作用 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `const char* terrainToName(Terrain terrain)` | 返回地形英文名，用 magic_enum 实现 | `terrain`：地形 | 常量字符串，失败返回 `"Unknown"` |
| `const char* terrainToChinese(Terrain terrain)` | 返回地形中文名 | `terrain`：地形 | 常量字符串，例如 `"空地"` |
| `const char* visibleTerrainToChinese(VisibleTerrain terrain)` | 返回可见地形中文名 | `terrain`：可见地形 | 常量字符串 |
| `bool terrainFromName(const std::string &name, Terrain &terrain)` | 由英文名解析地形，大小写不敏感 | `name`：地形名；`terrain`：输出参数 | 成功为 `true` |
| `VisibleTerrain toVisibleTerrain(Terrain terrain)` | 把真实地形转为视野内可见地形 | `terrain`：真实地形 | 可见地形 |
| `VisibleTerrain toFogTerrain(Terrain terrain)` | 把真实地形转为视野外疑似地形 | `terrain`：真实地形 | 可见地形 |

公开结构体：

- `struct Point`：坐标。公开变量 `int x = 0` 是行号，`int y = 0` 是列号。提供默认构造、`Point(int x, int y)` 构造、`operator ==`、`operator !=` 和 `std::string toString() const`（返回形如 `"(3, 5)"` 的字符串）。
- `struct Rank`：排名项。公开变量 `int id = 0` 是编号，含义由调用者决定，可以是玩家编号或队伍编号；`int rank = 0` 是名次，从 1 开始。

### 4.3 `src/include/map.hpp`

作用：游戏地图容器。用行优先一维数组保存二维格子。

命名空间：`gen::core`。

公开常量：

- `inline constexpr int NEUTRAL = -1`：中立格子的所有者编号。
- `inline constexpr int UNKNOWN = -2`：视野外未知格子的所有者编号。

公开模板结构体 `Tile<T>`：一个格子。

公开变量：

- `T terrain{}`：地形。
- `int owner = NEUTRAL`：所有者编号。
- `int unit = 0`：兵力。

公开成员函数：

| 函数 | 作用 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `Tile()` | 默认构造 | 无 | 无 |
| `Tile(T terrain, int owner, int unit)` | 构造格子 | 地形、所有者、兵力 | 无 |
| `bool isNeutral() const` | 是否中立 | 无 | 中立为 `true` |
| `bool isOwnedBy(int playerID) const` | 是否由指定玩家占领 | `playerID`：玩家编号 | 是则为 `true` |
| `std::string toString() const` | 返回可读格子信息 | 无 | 字符串 |

### 4.12 `src/core/config.cpp`

作用：配置读取与校验的实现。

主要流程：

1. 检查文件是否存在。不存在时抛出中文错误。
2. 用 `gen::json::parseFile` 解析文件。解析失败时把行列信息包进 `ConfigError`。
3. 检查根节点是否为对象。
4. 依次读取 `map`、`game`、`match`、`ui`、`log` 五段。
5. 段缺失时写警告，保留默认值。
6. 段内未知键写警告并忽略。
7. 键缺失时写警告，保留默认值。
8. 类型错误时抛出 `ConfigError`，消息含配置键路径。
9. 调用 `validate()` 做范围校验。
10. 读取成功后写日志。

校验规则：

| 配置键 | 允许范围 |
| --- | --- |
| `map.rows` | 5 到 200 |
| `map.cols` | 5 到 200 |
| `map.bannedTerrains` | 不允许 `blank` 与 `capital`，元素为地形英文名 |
| `map.cityProbability` 等三个概率 | 0 到 1，三个之和不超过 1 |
| `map.cityUnitsMin`、`map.cityUnitsMax` | 1 到 100000，且最小值不大于最大值 |
| `game.maxTurns` | 1 到 1000000 |
| `game.gamesPerMatch` | 1 到 1000 |
| `game.ffaPlayerCount` | 2 到 16 |
| `game.initTimeLimitMs` | 1 到 60000 |
| `game.turnTimeLimitMs` | 1 到 60000 |
| `game.maxViolations` | 0 到 1000 |
| `match.playerWeight`、`match.teamWeight` | 不小于 0，两者之和为 0 时只写警告 |
| `ui.cellSize` | 8 到 128 |
| `ui.turnDelayMs`、`ui.resultDelayMs` | 0 到 60000 |
| `log.directory` | 不能为空 |

队伍校验：

- 玩家 id 只能包含大小写英文字母、数字、下划线、短横线，长度 1 到 64。
- 玩家 id 不能重复。
- 1v1：必须 2 支队伍，每队 1 名玩家。
- 2v2：必须 2 支队伍，每队 2 名玩家。
- FFA：必须 `ffaPlayerCount` 支队伍，每队 1 名玩家。

### 4.16 `src/core/rule.cpp`

作用：规则实现。

`moveUnits` 的规则：

- 普通移动：移动 $u - 1$ 个兵力，源格保留 1 个。
- 一半移动：源格保留 $\lfloor u / 2 \rfloor$ 个，移动 $u - \lfloor u / 2 \rfloor$ 个。

`isValidMove` 的检查项：

1. 玩家编号不小于 0。
2. 源格在地图内。
3. 目标格在地图内。
4. 源格与目标格曼哈顿距离为 1。
5. 源格属于该玩家。
6. 源格兵力大于等于 2。
7. 目标格不是山区。

`applyMove` 的处理：

- 源格减少兵力，并更新统计。
- 目标为己方或队友：兵力相加，归属不变。
- 目标为敌方或中立，且移动兵力不大于目标兵力：目标兵力减少，归属不变，中立格不更新统计。
- 目标为敌方或中立，且移动兵力大于目标兵力：占领目标格，兵力为差值。
- 如果目标是敌方首都：占领后首都变城市，被击败玩家的全部格子归进攻方，非首都格兵力向上取整减半，被击败玩家记为死亡。

`applyEconomy` 的规则：

- 空地在回合数为 50 的倍数时加 1 个兵力。
- 城市和首都在偶数回合加 1 个兵力。
- 沼泽在兵力大于 1 时减 1 个兵力。
- 中立格子不生成也不消失兵力。

`eliminatePlayer` 的规则：

- 该玩家全部格子变为中立，兵力清零。
- 玩家记为死亡，更新队伍状态。

### 4.18 `src/core/game.cpp`

作用：游戏主体实现。

关键行为：

- 构造时先分配地图，生成器在 `initialize` 中填充。
- `recountStats` 从地图重新统计每名玩家和每支队伍的兵力与格子数。
- 排名排序规则：
  - 存活优先。
  - 存活单位按兵力降序、格子数降序、编号升序。
  - 死亡单位按死亡回合降序、死亡时兵力降序、编号升序。
- 最终排名规则：
  - 因胜利结束时，获胜队伍玩家占据最前，队内按最终兵力降序、玩家编号升序。
  - 其余玩家按死亡回合降序、死亡时兵力降序、玩家编号升序。
  - 到达最大回合数时，存活玩家先按队伍排名，再按兵力降序、玩家编号升序；已死亡玩家按死亡规则排在后面。
- `nextTurn` 顺序：
  1. 回合数加一。
  2. 按当前移动优先级执行移动。
  3. 处理兵力生成与消失。
  4. 判断剩余队伍数。小于等于 1 时结束。
  5. 轮转移动优先级。
  6. 判断是否到达最大回合数。
- `forfeitPlayer` 把玩家格子变中立，记录死亡回合为当前回合加一。
- `teamVision` 的视野规则：己方或队友占领的格子，以及与其切比雪夫距离不超过 1 的格子为可见格。可见格发送真实地形、归属和兵力。不可见格发送疑似地形，归属为 `UNKNOWN`，兵力为 0。

### 4.22 `src/core/score.cpp`

作用：计分实现。

计分公式：

$$
score = w_{player} \times (N - rank_{player} + 1)
      + w_{team} \times (T - rank_{team} + 1)
$$

其中 $N$ 为玩家总数，$T$ 为队伍总数，$w_{player}$ 为玩家权重，$w_{team}$ 为队伍权重。

实现细节：

- 玩家名次缺失或无效时跳过该玩家并写错误日志。
- 队伍权重为 0 时不计算队伍分。
- 队伍名次缺失或无效时跳过该玩家并写错误日志。
- 每名玩家的成绩按玩家 id 首次出现顺序建立。
- 累计时增加总分和局数，第一名次数单独累计。
- `ranking` 按总分降序排序，同分按玩家 id 升序，然后从 1 开始填名次。

### 4.26 `src/core/runner.cpp`

作用：总编排实现。

主要流程：

1. 决定界面是否开启。`--no-ui` 或 `ui.enabled = false` 时关闭。
2. 创建日志目录，失败时返回 1。
3. 写配置说明到日志。
4. 设置基础随机种子。优先级从高到低：`--seed`、`map.seed`、当前时间。
5. 扫描 `battle` 目录，发现可用玩家。
   - 目录名必须合法。
   - 必须有 `<id>.exe`。
   - 按 id 升序排列。
6. 构造比赛计划。
   - 开启自动匹配时，枚举 `C(n, k)` 种玩家组合，每种组合一场比赛。`n` 为可用玩家数，`k` 为当前模式需要人数。
   - 玩家数超过 300 时报错。组合数超过 2000 时写警告。
   - 关闭自动匹配时，按 `match.teams` 读取队伍和玩家，缺失的玩家报错返回 1。
7. 清空 `score.log`，配置计分权重。
8. 创建界面窗口。无界面模式跳过。
9. 逐场比赛。每场比赛跑 `gamesPerMatch` 局。
10. 每局开跑前计算随机种子：
    $$
    gameSeed = baseSeed \oplus (matchIndex \times 1000003) \oplus (gameIndex \times 9176)
    $$
11. 注册玩家，生成地图，写比赛开始日志和地形统计。
12. 创建操作记录文件，路径为 `logs/moves/match_XX_game_XX.log`。
13. 启动全部 AI 进程，标准错误写 `logs/ai/match_XX_game_XX_<id>.stderr.txt`。
14. 发送初始化消息：`PLAYER_SELF`、`PLAYERS`、`MAP_META`、`MAP`、`INIT`。
15. 等待玩家输出 `READY`。超时、输出不是 `READY`、进程退出时判负。
16. 回合循环：
    - 发送 `TURN` 和 `GO`。
    - 读取每名玩家的动作。
    - 按状态处理：
      - `Pass`：本回合不移动，连续违规清零。
      - `Move`：先用本回合开始前的地图做合法性预校验。合法就加入移动列表。不合法按 `PASS` 处理，记一次连续违规，日志写 `非法移动`。
      - `Invalid`：输出无法解析，按 `PASS` 处理，记一次连续违规，日志写 `非法输出`。
      - `Timeout`：超时，按 `PASS` 处理，记一次连续违规。
      - `Eof`：输出结束，立即判负。
      - `Crashed`：进程崩溃，立即判负。
    - 连续违规达到 `maxViolations` 时判负。
    - 调用 `Game::nextTurn` 执行移动。
    - 写操作记录。
    - 无界面模式下不绘制画面。
17. 一局结束：发送 `GAME_OVER`，关闭输入，等待进程退出，必要时强制结束。
18. 用户按 `Esc` 时中止本次运行，本局不计分，返回 1。
19. 正常结束时写入计分，打印本局排名和累计排名，追加到 `score.log`。
20. 全部比赛结束后打印最终排名。

其他说明：

- 玩家判负后，其通道关闭。后面回合不再读取该玩家动作。
- 界面模式每回合绘制两次画面，并对暂停、退出、视野、播放速度做响应。
- `--seed` 为 0 时使用 `map.seed`。两者都为 0 时使用时间种子。
- 退出码 1 也会在用户中途退出时返回。

### 4.28 `src/io/io.cpp`

作用：通信通道实现。

关键行为：

- `start` 检查可执行文件和工作目录是否存在。
- 创建标准输入管道、标准输出管道。
- 标准错误重定向到文件，文件位于 `logs/ai/` 下。
- 用 `CreateProcessA` 启动进程，隐藏窗口，不创建控制台。
- `sendFrame` 写 4 字节小端序长度，再写 1 字节类型，再写负载。
- 写入循环处理短写。读取循环处理短读。
- 单行输出上限为 64 KiB，输出缓冲上限为 1 MiB。
- 读取超时按毫秒计时，先让步式轮询，后短睡眠。
- `readAction` 解析动作：
  - `PASS` 返回 `Pass`。
  - `M x1 y1 x2 y2` 返回普通移动。
  - `H x1 y1 x2 y2` 返回一半移动。
  - 其他内容返回 `Invalid`，包括空行、参数数量错误、坐标不是整数。
- 这里只判断动作格式。棋盘上的合法性由 `Runner` 用本回合开始前的地图预校验。
- `closeInput` 关闭父进程写端，通知 AI 对局结束。
- `terminate` 强制结束进程并等待退出。
- 全部失败路径都写日志，日志来自 `include/logger.hpp`。

### 4.30 `src/io/protocol.cpp`

作用：协议编码实现。

关键行为：

- 所有整数小端序。
- 玩家 id 最多写 64 字节，超出时截断。
- 统计值出现负数时按 0 处理并写警告。
- 编号超过 `uint16` 上限时按上限处理并写警告。
- 条目数量超过 `uint16` 上限时按上限截断并写错误日志。
- 单帧负载超过 `MAX_FRAME_BYTES` 时写错误日志。
- `map_payload` 依次写三组数组：
  - `uint8 terrain[R * C]`：地形，编码 0 到 7。
  - `int16 owner[R * C]`：归属，-1 中立，-2 未知，其他为玩家编号。
  - `uint32 units[R * C]`：兵力，未知格为 0。
- `TURN` 依次写：回合数、玩家数量、玩家状态、队伍数量、队伍排名、地图负载。
- `GAME_OVER` 写玩家排名和队伍排名，玩家死亡回合 -1 表示存活。

## 六 通信协议位置

通信协议的权威文本在 [选手须知](../选手须知.md) 的通信协议一节。开发计划里的协议最终版在 `LLM_notice/开发计划.md` 第五节。

代码实现位置：

| 位置 | 内容 |
| --- | --- |
| `src/io/protocol.hpp` | 消息类型常量、编码函数声明 |
| `src/io/protocol.cpp` | 负载编码实现 |
| `src/io/io.hpp` | 通信通道接口 |
| `src/io/io.cpp` | 管道读写、动作解析、超时处理 |
| `battle/example/example.cpp` | 客户端参考实现 |

协议要点：

- 服务器发消息：4 字节小端序长度加负载。负载首字节为消息类型。
- AI 发消息：每回合输出一行 ASCII 动作，以换行结尾。
- 所有整数小端序。
- 坐标从 0 开始，`x` 为行，`y` 为列，行优先下标为 $idx = x \times C + y$。
- 动作有三种：`PASS`、`M x1 y1 x2 y2`、`H x1 y1 x2 y2`。
- 普通移动源格保留 1 个兵力。一半移动源格保留 $\lfloor u / 2 \rfloor$ 个兵力。
- 超时、非法输出、非法移动按 `PASS` 处理并记违规。
- 进程退出、崩溃、输出结束判负。

## 七 执行流程：main 到 Runner 到 Game 到 Rule

```text
main
  解析参数
  读取配置
  初始化日志
  创建 Runner
  Runner::run
       计算基础种子
       扫描 battle 目录
       生成比赛计划
       创建界面
       对每场比赛
           对每局
               Game 构造
               registerPlayer
               initialize
                    MapGenerator::generate
               AIChannel::start
               发送初始化消息
               等待 READY
               回合循环
                   send TURN GO
                   readAction
                   Game::nextTurn
                        Rule::applyMove
                        Rule::applyEconomy
                        判断胜负
                        轮转移动优先级
                   记录与绘制
               发送 GAME_OVER
               ScoreBoard::addGame
            打印累计排名
       打印最终排名
```

职责划分：

- `main.cpp` 只做参数、配置、日志和异常处理。
- `Runner` 负责进程级的组织：玩家发现、比赛安排、AI 进程、计时、判负、日志、计分。
- `Game` 负责一局游戏的状态和回合流程。
- `Rule` 负责单步规则：移动是否合法、如何执行、兵力如何变化。
- `MapGenerator` 只负责生成地图和首都。
- `AIChannel` 只负责进程通信，不关心游戏规则。
- `protocol` 只负责字节编码，不关心业务逻辑。
- `Renderer` 只负责绘制，不修改游戏状态。
- `ScoreBoard` 只负责累计分数。

## 八 构建系统说明

根目录 `build.bat` 分三步：

1. 检查编译器。执行 `where g++`，找不到时打印英文提示并退出，退出码 1。
2. 编译主程序 `serve.exe`。先删除旧文件，再调用 g++。
3. 编译示例玩家。依次尝试 `example`、`demo_expand`、`demo_random`、`demo_rush`。每个子目录里的 `build.bat` 会被调用。缺失或失败时写警告，不中断主构建。

编译命令：

```bat
g++ -std=gnu++20 -finput-charset=UTF-8 -fexec-charset=UTF-8 -static -O2 -Wall -Wextra -Wno-unknown-pragmas -Wno-unused-parameter -Isrc -Ilib -o serve.exe src\main.cpp src\core\*.cpp src\io\*.cpp src\ui\*.cpp -Llib\easyx\lib -leasyx -lgdi32 -lole32 -lwinmm -lgdiplus
```

参数含义：

| 参数 | 含义 |
| --- | --- |
| `-std=gnu++20` | 使用 C++20 标准，允许 GNU 扩展 |
| `-finput-charset=UTF-8` | 源文件使用 UTF-8 编码 |
| `-fexec-charset=UTF-8` | 程序内字符串使用 UTF-8 编码 |
| `-static` | 静态链接 GCC 运行时和标准库 |
| `-O2` | 开启常用优化 |
| `-Wall`、`-Wextra` | 打开常用警告 |
| `-Wno-unknown-pragmas` | 忽略 EasyX 头文件里的 `#pragma comment` 警告 |
| `-Wno-unused-parameter` | 忽略部分未使用参数警告 |
| `-Isrc` | 头文件搜索路径 `src` |
| `-Ilib` | 头文件搜索路径 `lib` |
| `-o serve.exe` | 输出文件名 |
| `src\main.cpp src\core\*.cpp src\io\*.cpp src\ui\*.cpp` | 全部源文件 |
| `-Llib\easyx\lib` | EasyX 静态库搜索路径 |
| `-leasyx` | 链接 EasyX 静态库 |
| `-lgdi32 -lole32 -lwinmm -lgdiplus` | 链接 Windows 系统库 |

输出位置：

- 主程序：仓库根目录 `serve.exe`。
- 示例玩家：各自目录，例如 `battle/example/example.exe`。

静态链接验证方法见 [构建与环境](构建与环境.md)。

## 九 测试方案与新增测试

测试方案：

- 全部测试使用 `--no-ui` 无界面模式。
- 测试脚本是 `tests/run_tests.ps1`。脚本兼容 Windows 自带的 Windows PowerShell 5.1，不需要安装 PowerShell 7。
- 测试脚本文件必须保存为 UTF-8 BOM 编码，否则 5.1 读取中文会乱码。
- 每个测试记录命令、配置、退出码和关键日志。
- 测试结果写到 `build/test_output/`。汇总报告是 `build/test_output/report.md`，每次运行都会重新生成。
- 项目约定的报告归档位置是 `LLM_notice/测试报告.md`。验收结束后人工归档。
- 禁止伪造测试结果。不能测的项目要写原因。

当前脚本共有 47 项检查。最近一次验收测试 47 项全部通过，报告在 `build/test_output/report.md`。

覆盖范围：

- 干净构建与构建产物检查。
- 示例配置。
- 1v1、2v2、FFA。
- 自动匹配。
- 禁用地形。
- 最大回合数。
- AI 超时、崩溃、非法输出、非法移动。
- 日志目录缺失、配置缺失、玩家可执行文件缺失、自动匹配人数不足。
- 界面冒烟测试。

新增测试的步骤：

1. 在 `tests/ai/` 增加测试用 AI 源码。例如超时 AI、崩溃 AI、非法输出 AI、非法移动 AI。
2. 编译测试用 AI，输出到 `tests/ai/` 或临时目录。
3. 在 `tests/` 增加所需配置文件。测试配置可以引用测试用 AI。
4. 在 `tests/run_tests.ps1` 中增加测试项。
5. 测试项要有唯一名称、独立输出目录、明确的退出码或日志断言。
6. 运行脚本，确认新测试项通过，并把结果写入报告。
7. 如果修改了 `tests/run_tests.ps1`，保存时保持 UTF-8 BOM 编码。

详细步骤见 [测试说明](测试说明.md)。

## 十 外部库与静态链接

| 库 | 类型 | 链接方式 | 文档 |
| --- | --- | --- | --- |
| EasyX | 静态库 | `-Llib/easyx/lib -leasyx`，再链接 Windows 系统库 | <https://easyx.cn> |
| magic_enum | 纯头文件 | 只加 `-Ilib` | <https://github.com/Neargye/magic_enum> |

说明：

- EasyX 以 `.a` 静态库提供。不需要安装，不需要运行时 DLL。
- magic_enum 是纯头文件库。不需要链接。
- 项目要求全部静态链接。运行时不依赖 MinGW 的 `libstdc++-6.dll`、`libgcc_s_*.dll`、`libwinpthread-1.dll`。
- 新增外部库时，必须遵循 `lib/库名/` 的目录规范，并且不能引入运行时动态库。

## 十一 已知限制

1. 玩家 AI 没有系统级沙箱。AI 以当前用户权限运行，能访问当前用户能访问的文件。只运行可信 AI。
2. 自动匹配会枚举全部玩家组合。玩家多时组合数量增长很快，比赛时间会变长。玩家数超过 300 时程序报错。
3. 界面使用 EasyX，只支持 Windows。
4. 操作记录文件可能较大。长对局时建议按需要关闭 `log.recordMoves`。
5. 计分只在正常结束时累计。用户按 `Esc` 中止时，当前局不计分。
6. 协议中玩家和队伍数量使用 `uint16` 表达，玩家数上限为 32767。自动匹配额外限制为 300。
